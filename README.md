# Crypto Research System

## Цель

Системная исследовательская платформа для анализа криптоактивов.

## Методология

**Задача → Исследование → Факты → Анализ → Результат → Мониторинг**

Методология и формат исследования определены в **CryptoResearch v2 / Structure 1**.

## Текущий порядок работ

Работа ведётся строго по этапам:

1. **Hosting architecture и inventory зависимостей.** Зафиксировать целевую архитектуру размещения, выяснить фактические зависимости от Cloudflare и Neon. VPS пока не разворачивать; production migrations не запускать.
2. **Полный аудит Product Contour v1.** Сопоставить репозиторий, миграции, фактическую схему/данные, API, Worker, UI и CI. Отделять подтверждённое состояние от предположений и непроверенных account-level фактов.
3. **Один полный продуктовый сценарий на BTC.** Проверить связный путь от источников и observations до Evidence, Domains, Factors, Scores, Bull/Base/Bear Scenarios, Monitoring, API и UI.
4. **Расширение данных и исследований.** Только после подтверждения BTC-сценария и закрытия блокирующих дефектов переходить к расширению покрытия других активов.

## Первый продуктовый сценарий

**BTC — первый актив для полного доказанного продуктового сценария.**

Это не означает удаления или игнорирования ETH и других активов: они остаются в реестре и в общей матрице аудита. Однако расширение исследований и создание новых активных сценариев для других активов не должно опережать завершение BTC-пути.
