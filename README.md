# Crypto Research System

> **Repository description:** Self-hosted crypto research platform for source-traceable data, reproducible asset scenarios, evidence, and monitoring.

## Цель

Исследовательская платформа для анализа криптоактивов: от проверяемых первичных данных и факторов до воспроизводимых сценариев, evidence и мониторинга.

## Текущий этап

Текущий рабочий фокус — довести **один полный сценарий BTC** до воспроизводимой оценки на проверенных входных данных. До оценки обязательны проверка происхождения источников, единиц измерения, временных меток, свежести, ревизий и повторяющихся логических записей.

Данные-кандидаты и документы по контрактам источников не являются разрешением на автоматическую запись. Сценарная readiness-проверка остаётся read-only и не записывает состояние сценария.

## Архитектурное направление

- Целевой runtime — собственный хостинг/VPS: PostgreSQL, API и отдельный Worker за HTTPS reverse proxy.
- GitHub Actions используются для CI и проверок, а не как runtime приложения.
- Cloudflare и Neon не являются целевыми зависимостями архитектуры.
- Существующие внешние сервисы не отключаются до появления хоста, проверки backup/restore, read-only parity, E2E-приёмки, плана отката и отдельного согласования переключения.

## Контракт данных BTC

Ключевые входы текущего сценария: spot price, hashrate, fee/subsidy ratio, ETF net flows и DXY. Для каждого входа нужны зарегистрированный источник, исходная единица, время наблюдения отдельно от времени получения, проверка свежести и контролируемая обработка ревизий/дубликатов.

Текущий статус входов и ограничения зафиксированы в:
- `docs/BTC-SOURCE-CONTRACT-AND-CANDIDATE-INPUTS-2026-10-12.md`
- `data/CryptoDataModel/candidates/btc-input-snapshot-2026-10-12.json`

Этот snapshot намеренно неполный: он не предназначен для загрузки в БД; сценарная оценка блокируется, пока все обязательные входы не пройдут проверки.

## Принципы изменений

- Не считать отсутствующие значения нулём.
- Не подменять первичный источник похожим показателем без пересмотра контракта и методологии.
- Не удалять дубликаты и не перезаписывать ревизии автоматически.
- Не записывать состояние сценария и не менять production без отдельного согласования.
